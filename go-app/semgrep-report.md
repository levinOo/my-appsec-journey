**Дата сканирования:** Текущая дата
**Инструмент:** `Semgrep OSS` (Open Source Version)
**Статус:** 🔴 **Критический (Найдены блокирующие уязвимости)**

## 📊 1. Executive Summary (Краткая сводка)

В ходе автоматизированного сканирования исходного кода с помощью Semgrep OSS было обнаружено **9 блокирующих (Blocking) инцидентов безопасности**. Сканер успешно выявил критические уязвимости внедрения (Injection), а также указал на архитектурные недостатки (отсутствие шифрования трафика) и риски межсайтового скриптинга (XSS).

**Статистика по типам угроз:**
* 🔴 **Критические (SQLi, Command Injection):** 3
* 🟡 **Средние (Отсутствие TLS, XSS):** 6

## 🚨 2. Разбор критических уязвимостей (High Severity)

### 2.1. SQL Injection via Taint Analysis (CWE-89)
* **Правила:** `tainted-sql-string`, `string-formatted-query`
* **Файл:** `internal/handlers/user.go:14`
* **Описание:** Обнаружено прямое попадание пользовательских данных в SQL-запрос, сформированный вручную через форматирование строк. Злоумышленник может манипулировать запросом для кражи или изменения данных в БД.
* **Рекомендация:** Использовать подготовленные выражения (`db.Query("SELECT * FROM users WHERE username = ?", name)`) или безопасную ORM-библиотеку.

### 2.2. Command Injection (CWE-78)
* **Правило:** `dangerous-exec-command`
* **Файл:** `internal/handlers/system.go:15`
* **Описание:** Использование нестатической команды внутри `exec.Command`. Непроверенные данные от пользователя достигают места вызова функции, что приводит к уязвимости внедрения кода (RCE - Remote Code Execution).
* **Рекомендация:** Валидировать входные данные (использовать регулярные выражения для проверки IP-адресов) или полностью отказаться от вызова системной оболочки `sh -c`.

## ⚠️ 3. Проблемы средней критичности и архитектуры (Medium Severity)

### 3.1. Передача данных в открытом виде (CWE-319)
* **Правило:** `use-tls`
* **Файл:** `cmd/server/main.go:26`
* **Описание:** Сервер запускается с использованием `http.ListenAndServe`, что означает передачу всего трафика (включая токены и пароли) в открытом виде.
* **Autofix от Semgrep:** Использовать `http.ListenAndServeTLS(":8080", certFile, keyFile, nil)`.
* **Рекомендация:** Настроить терминацию TLS на уровне балансировщика (Nginx/Traefik) или использовать SSL-сертификаты прямо в приложении.

### 3.2. Cross-Site Scripting / XSS (CWE-79)
* **Правила:** `no-direct-write-to-responsewriter`, `no-printf-in-responsewriter`
* **Файлы:** `internal/handlers/system.go`, `internal/handlers/user.go` (множественные срабатывания)
* **Описание:** Прямая запись неэкранированных данных или форматированных строк в `http.ResponseWriter`. Это обходит встроенные механизмы HTML-экранирования и делает возможным выполнение вредоносного JS-кода в браузере пользователя.
* **Рекомендация:** Использовать пакет `html/template` и метод `template.Execute()` для безопасного рендеринга данных, возвращаемых клиенту.

---

## 🛠 4. План действий (Remediation Plan)

1. Устранить уязвимости инъекций (SQLi и RCE) до развертывания приложения.
2. Рассмотреть интеграцию `Semgrep` в пайплайн проверки Pull Request (PR) для блокировки небезопасного кода на этапе ревью.
3. **Примечание аудитора:** Для полноценного покрытия (в частности, для поиска секретов и сложных Taint-цепочек) рекомендуется дополнить пайплайн специализированными инструментами (например, Gitleaks) или использовать коммерческую версию правил (Semgrep Pro).
